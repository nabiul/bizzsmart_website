# Accounts and double-entry accounting

Verified from the application source on 2026-09-15.

Financial operations are material changes. Confirm the active location, account, contact, purpose, amount, date, and payment method before saving. Never advise direct database corrections.

## Account master data

- **Accounts → Banks** manages cash/bank accounts available to financial forms.
- **Accounts → Purposes** manages income/expense/both-purpose classifications.
- **Accounts → Payeer/Payee** manages named payers and payees that can be selected in transactions.

Create required account and purpose records before entering deposits, withdrawals, or transfers. Access depends on separate view/create/edit/delete permissions.

## Create a deposit / credit

Required permission: `deposite create` or the configured deposit-create permission.

1. Open **Accounts → Deposit / Cr**.
2. Select the new-deposit action.
3. Enter **Deposit Date**.
4. Select **Bank** and **Purpose**. These fields are required.
5. Enter **Total Amount**. It must be numeric.
6. Select **Contact** or **Payer** when the receipt belongs to one.
7. Review the displayed **Balance**.
8. Select **Payment Method** when displayed.
9. For cheque payment, enter **Cheque No**, **Bank Name**, and **Cheque Date**.
10. Optionally enter **Money Receipt**, **Note**, and attach **Select File**.
11. Select **Save** once and verify the resulting voucher.

Uploaded files are limited to 2 MB by the current controller validation. Deposits linked to a sale or subsidy cannot exceed the eligible remaining amount.

## Create a withdrawal / debit

Required permission: `withdraw create` or an equivalent privileged role.

1. Open **Accounts → Withdraw / Dr**.
2. Select the new-withdrawal action.
3. Enter **Withdraw Date**.
4. Select **Account** and **Purpose**.
5. Select **Withdraw Type** and **Withdraw Method**.
6. Enter **Total Amount**.
7. Select **Contact**, **Payee**, or **Project** when applicable.
8. Review the displayed **Balance**.
9. For cheque payment, enter **Cheque No**, **Bank Name**, and **Cheque Date**.
10. Optionally enter **Money Receipt**, **Note**, and attach **Select File**.
11. Select **Save** once and verify the voucher.

Uploaded files are limited to 2 MB. Employee-advance and project-related withdrawal flows may open this screen with additional context; keep that context intact.

## Transfer between accounts

Required permission: `transfer create` or an equivalent privileged role.

1. Open **Accounts → Transfer**.
2. Select the new-transfer action.
3. Enter **Transfer Date**.
4. Select **Bank From** and **Bank To**.
5. Review both displayed balances.
6. Enter **Total Amount**.
7. Optionally enter **Money Receipt** and **Note**.
8. Select **Save** and verify the transfer voucher.

The source and destination cannot be the same account. A transfer creates linked debit and credit effects under the same transfer voucher.

## Batch deposits, withdrawals, and transfers

The application contains batch workflows for deposits, withdrawals, and transfers. Use them only when the user understands every included line. Verify the total against the individual entries before saving.

## Suspended deposits and withdrawals

The application can resume or remove certain suspended transactions. Before entering a replacement, check whether a suspended record already exists to prevent duplication.

## Expense requests

Use **Accounts → Expense Request** to review expense requests. Approval is a separate action. Only an authorized approver should approve an expense after verifying purpose, requester, evidence, and amount.

## Double Entry Accounting

When enabled, this menu provides:

- **Chart of Accounts** for account hierarchy.
- **Journal Entries** for manual journal records.
- **Trial Balance**.
- **Balance Sheet**.
- **Income Statement**.
- **General Ledger**.
- **Account Statement**.

## Create a journal entry

1. Open **Double Entry Accounting → Journal Entries**.
2. Select the create action.
3. Enter the transaction date and description/reference requested by the form.
4. Add debit and credit lines using valid chart-of-account entries.
5. Confirm total debits equal total credits.
6. Save and review the entry.

Never use a manual journal to hide or duplicate a transaction already generated by Sales, Purchase, Deposit, Withdraw, Transfer, Payroll, or another integrated module. Consult the authorized accountant when correcting posted entries.

## Financial troubleshooting

### The balance looks wrong

1. Verify the current location and date range.
2. Check the account statement and relevant source transaction.
3. Check whether the transaction is suspended, deleted, returned, or linked to another voucher.
4. Check manual journal entries.
5. Escalate to an authorized accountant; do not directly edit database balances.

### A duplicate voucher may have been created

Stop entering new transactions. Search by contact, date, amount, receipt/reference, and voucher number. Ask an authorized user to determine which record should remain and use the application's approved reversal/delete workflow.
